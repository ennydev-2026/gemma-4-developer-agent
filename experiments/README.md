# TRUST-SWE experiment protocol

Do not modify `submission/` in place during a measured run. Snapshot the full
configuration and record the exact model/harness pair.

## Directory convention

```text
experiments/<run-id>/
├── manifest.json
├── submission/          # immutable config snapshot
├── task_results.jsonl   # raw harness output
├── summary.json         # generated by summarize_results.py
└── notes.md
```

Recommended run id:

```text
YYYYMMDD-<variant>-<split>-<seed>
```

## Required manifest fields

- git commit SHA;
- harness and `adk_submission` versions;
- model/checkpoint and adapter hashes;
- variant (`lexical-only`, `graph-first`, `trust-prompt`,
  `trust-router-lora`, or `trust-full`);
- task ids and split definition;
- random seed;
- generation config;
- task/tool/turn budgets;
- machine/GPU description.

## Split discipline

Maintain both chronological splits and leave-one-repository-out folds. A task
must not appear in validation after any oracle-derived information from that
task entered a prompt, skill, preference pair, or adapter.

## Summaries

Generate the common scorecard:

```bash
python3 scripts/summarize_results.py \
  experiments/<run-id>/task_results.jsonl \
  -o experiments/<run-id>/summary.json
```

Inspect raw traces for:

- graph lookup followed by a justified fallback;
- repeated or equivalent tool calls;
- correct use of the analyzer trigger;
- reproduction before editing;
- empty patches, budget exhaustion, and regressions.

## Promotion gate

Promote a policy or adapter only when it:

1. improves resolution on more than one held-out fold;
2. does not rely on a single repository;
3. stays inside the total inference budget;
4. does not increase invalid/empty patches;
5. has a recorded ablation against the immediately preceding version.
